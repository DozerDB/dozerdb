# DozerDB 5.26.32.1

Long-term-support release on Neo4j 5.26.32: it adds Neo4j-compatible metrics.

| | |
| --- | --- |
| Neo4j baseline | `5.26.32` (commit `27f24499b751708815d42c8cf26bfb6597b3516c`) |
| Components | core `5.26.32-1.1.0`, metrics `5.26.32-1.1.0`, Browser `5.26.32.1`, plugin `5.26.32.1` |
| Runtime | Java 17 or 21; the Docker image ships Temurin 21 on Debian Trixie |
| Docker | `graphstack/dozerdb:5.26.32.1`, `graphstack/dozerdb:5.26` |

## What is in this release

- Metrics as the Neo4j Operations Manual 5 documents them: every
  `server.metrics.*` setting and `server.directories.metrics` with Neo4j's
  name, default and validation, the documented metric names and types, and
  four ways to read them: CSV files, JMX MBeans, a Prometheus endpoint and a
  Graphite exporter. A `neo4j.conf` written for Neo4j's metrics starts DozerDB
  unchanged.
- Of the 249 metrics in Neo4j's 5 reference, 141 are Compatible and 42
  Partial; the other 66 measure clustering, which a single server does not
  have. The [compatibility matrix](../monitoring/compatibility-matrix.md)
  lists every metric and the [differences page](../monitoring/differences.md)
  gives the reason for each one that is not fully compatible.
- The plugin JAR, the standalone archives and the Docker image carry the same
  metrics. The Docker image writes CSV metrics to `/metrics`, and the
  Prometheus endpoint is reachable from the host with
  `NEO4J_server_metrics_prometheus_endpoint=0.0.0.0:2004`
  ([enable and expose metrics](../monitoring/enable-and-expose.md)).
- DozerDB Browser `5.26.32.1`: `:sysinfo` fills its store size, page cache
  and transaction figures from these metrics.
- `neo4j-admin server report` collects the metrics directory.

## Compatibility notes

- Metrics are on by default, as in Neo4j: with no metrics setting, DozerDB
  writes CSV files to the metrics directory and registers JMX MBeans for the
  metrics Neo4j's default filter enables. Set `server.metrics.enabled=false`
  to switch them off. Prometheus and Graphite stay off until enabled.
- Never expose the Prometheus endpoint to the Internet directly; its default
  `localhost:2004` is reachable from the same host only.
- DozerDB 5.26.32.1 is built on the same Neo4j `5.26.32` as 5.26.32.0; data
  directories from earlier DozerDB 5.26 releases open unchanged.
- The Windows archive is verified by inspection of its contents and launchers;
  it is not run as part of the release checks.
- Neo4j's Cypher `WAIT` clause on database management commands is not
  supported.

## Verification

The release archives, the plugin JAR and the Docker image passed the packaged
smoke tests, the metrics checks (CSV, JMX and a real Prometheus scraping each
of them), the Cypher constraint and database lifecycle flow and the Browser flow
described in [building.md](../building.md). Checksums are published beside
each file on the GitHub release.
