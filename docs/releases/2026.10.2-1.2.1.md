# DozerDB 2026.10.2-1.2.1

DozerDB 1.2.1 on Neo4j `2026.10.2`. Updates the Neo4j calendar baseline and fixes parameter handling in database and user administration commands.

| | |
| --- | --- |
| Neo4j tag and commit | `2026.10.2` (commit `11fe55832db7219cbdb9e4535cda9795a069610e`) |
| DozerDB version | `1.2.1` |
| Distribution version | `2026.10.2-1.2.1` |
| Components | all DozerDB JARs `2026.10.2-1.2.1` |
| Runtime | Java 21 or newer; the Docker image ships Temurin 21 on Debian Trixie |
| Docker | `graphstack/dozerdb:2026.10.2-1.2.1` (immutable), `graphstack/dozerdb:2026.10` and `graphstack/dozerdb:latest` |

## What is in this release

- Neo4j 2026.10.2 corrects a transitive dependency exclusion in its testing tools.
- Parameterized STOP, START and DROP DATABASE commands now resolve database
  names consistently, including mixed-case values and quoted parameter names.
- User administration accepts quoted and Unicode password parameter names,
  including password changes by the current user.
- Metrics, query logging and `dbms.setConfigValue` retain the 1.2 feature set.
- Open GDS 2026.10.2 is the companion plugin for this Neo4j version.

## Compatibility notes

- Use the plugin JAR with the exact Neo4j Community `2026.10.2` baseline.
- Cross-line store migration is not validated by this release. Back up existing
  data before upgrading.
- Query logging remains enabled at VERBOSE by default. See
  [query logging](../monitoring/query-logging.md) for its settings and cost under load.
- The Windows archive is checked statically; its launchers are not executed
  on a Windows host in the release checks.
- The Cypher WAIT clause on database management commands remains unsupported.
